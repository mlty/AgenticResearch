# Failure Analysis 模块文档

## 1. 模块定位

Failure Analysis 专门分析失败实验、异常日志、指标退化和实现问题，帮助用户把失败转化为可执行的修复或迭代建议。

## 2. 用户价值

1. 减少排查实验失败的时间。
2. 把失败原因结构化沉淀。
3. 形成下一轮实验的明确改动方向。

## 3. 用户故事

```text
作为算法工程师，我希望系统自动总结实验失败原因，以便我知道应该先检查数据、代码、超参还是方法假设。
```

## 4. MVP 功能范围

### 4.1 必须做

- [ ] 读取失败实验日志。
- [ ] 识别常见错误类型。
- [ ] 区分运行失败和效果失败。
- [ ] 生成修复建议。
- [ ] 写入 Experiment Memory。

### 4.2 暂不做

- [ ] 自动修复所有代码错误。
- [ ] 自动解释所有指标退化。
- [ ] 替代用户做最终研究判断。

## 5. 页面与交互

核心视图：

1. 失败实验列表。
2. 错误摘要。
3. 可能原因排序。
4. 建议操作。
5. 一键创建修复任务或重跑实验。

## 6. 数据对象

| 对象 | 用途 |
| --- | --- |
| FailureReport | 失败分析报告 |
| FailureCause | 可能原因 |
| LogSnippet | 关键日志片段 |
| SuggestedFix | 修复建议 |
| Experiment | 关联实验 |

## 7. API / 事件

| 类型 | 名称 | 说明 |
| --- | --- | --- |
| API | `POST /api/experiments/{experiment_id}/failure-analysis` | 分析失败实验 |
| API | `POST /api/failure-reports/{report_id}/actions` | 创建修复动作 |
| Event | `failure.analysis_completed` | 分析完成 |
| Event | `failure.fix_created` | 修复任务创建 |

## 8. 状态与异常

| 状态 | 处理方式 |
| --- | --- |
| Missing logs | 提示无法分析并要求补充日志 |
| Unknown failure | 标记为 unknown 并建议人工检查 |
| Multiple causes | 按置信度排序展示 |
| Fix risky | 要求用户确认后执行 |

## 9. 验收标准

- [ ] 系统能对失败实验生成报告。
- [ ] 报告能指出关键日志片段。
- [ ] 报告能给出至少一个下一步建议。
- [ ] 用户能从报告创建修复或重跑任务。
